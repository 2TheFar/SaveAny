# SaveAny 项目计划书

更新时间：2026-05-06

## 项目定位

SaveAny 是一个面向普通用户的视频保存与内容处理工具。当前已经完成“公开视频下载”核心链路，接下来不急着做视觉精修，而是先把付费功能的核心能力做出来，包括视频总结、字幕提取、字幕翻译、音频提取、批量任务等。

总体策略：

```text
先完成核心功能闭环
-> 再做 UI/体验精修
-> 最后做账号、额度、支付、部署正式化
```

## 当前状态

下载功能已经完成 MVP 闭环：

- YouTube 可解析、可下载，封面图可通过后端缓存显示。
- Bilibili 可下载 1080p。
- 抖音精选和抖音视频可通过专用 Resolver 解析与下载。
- FastAPI 后端已经搭建，支持解析、任务下载、任务状态、文件返回、环境自检。
- Next.js 已转为产品入口 + BFF，配置 `SAVEANY_BACKEND_URL` 后优先调用 FastAPI。

当前项目仍处于 MVP 扩建阶段，不是正式发行版。

## 阶段路线

### 阶段 1：MVP 可行性验证（已完成）

目标：证明“粘贴链接 -> 解析视频 -> 选择质量 -> 下载文件”的核心链路可行。

已完成：

- 搭建 Next.js + React + TypeScript 单体 MVP。
- 实现首页、链接输入、质量选择、任务状态、结果卡片、Pro 展示区。
- 通过 Next.js Route Handlers 调用 `yt-dlp`。
- 实现 `POST /api/video/info`、`POST /api/video/download`、`GET /api/video/file/:id`。

结论：核心链路可行，但单体结构不适合承载复杂任务和后续 AI 功能。

### 阶段 2：Resolver 架构重整（已完成）

目标：从“所有平台都交给 yt-dlp”升级为“平台识别 + 平台专用 Resolver + yt-dlp 通用兜底”。

已完成：

- 建立平台识别策略。
- 建立统一 Resolver 返回模型。
- 增加 `YtDlpResolver`。
- 增加 `DouyinResolver`，解决 `yt-dlp` 不支持抖音精选链接的问题。
- 明确 Cookie 策略：公网版本默认不接收、不保存、不使用用户 Cookie。
- 增加结构化错误类型。

结论：不能把 `yt-dlp` 当作唯一方案，它应该是通用兜底能力；特殊平台需要专用 Resolver。

### 阶段 3：FastAPI 下载后端雏形（已完成）

目标：把下载能力从 Next.js 单体中拆出，形成可扩展后端服务。

已完成：

- 新增 FastAPI 后端。
- 实现系统自检、解析接口、下载任务接口、任务状态接口、文件返回接口、缩略图缓存接口。
- 抖音走专用 Resolver + 后端代理下载。
- YouTube/Bilibili 等通用平台走 `yt-dlp`。
- Next.js BFF 优先调用 FastAPI，失败时回落本地能力。

结论：下载功能可以在此沉淀，后续功能应基于 FastAPI 任务模型继续扩建。

### 阶段 4：付费功能核心开发（下一阶段）

目标：先把视频总结、字幕提取、字幕翻译等 Pro 功能的技术闭环做出来，再做 UI 精修。

阶段 4 不以“页面好看”为第一目标，而以“功能能跑通、接口边界清晰、可被前端调用”为第一目标。

计划功能：

- 视频总结：输入视频链接，生成摘要、章节、要点、时间戳。
- 字幕提取：优先读取平台字幕；没有字幕时走音频提取 + 语音转文字。
- 字幕翻译：将字幕翻译为中文/英文等目标语言。
- 音频提取：为转写、总结、下载音频做基础能力。
- 任务结果管理：保存任务结果结构，前端可轮询查看。
- 竞品分析输入：另开窗口产出的竞品分析将作为第四阶段需求来源。

验收标准：

```text
至少一个公开视频链接
-> 创建视频总结任务
-> 后端提取音频或字幕
-> 生成结构化总结结果
-> 前端能展示结果
```

### 阶段 5：产品体验精修与 Pro 引导

目标：在功能闭环完成后，再打磨普通用户体验和付费转化。

计划内容：

- 前端任务轮询 UI。
- 下载进度与 AI 处理进度展示。
- 更清晰的错误文案。
- Pro 功能入口和权益展示。
- 平台能力展示。
- 移动端体验优化。
- 继续参考 `ai.codefather.cn/painting` 的白底、强蓝、大标题、圆角输入框、内容卡片风格。

### 阶段 6：正式化扩展与部署准备

目标：为真实用户测试和小规模发行做准备。

计划内容：

- Docker 化部署 Next.js + FastAPI + `yt-dlp` + `ffmpeg`。
- 引入数据库，保存用户、任务、额度、订单、历史记录。
- 引入 Redis/RQ 或 Celery，替代内存任务表。
- 引入对象存储，替代本地临时文件。
- 增加账号、额度、支付、订阅状态。
- 增加过期文件清理和任务清理。

## 当前统一架构

```text
浏览器
  -> Next.js
     - 产品页面
     - 工作台 UI
     - BFF API
     - 未来登录/支付入口
  -> FastAPI
     - 平台识别
     - Resolver 调度
     - 下载任务
     - AI 任务
     - 文件与结果管理
  -> Resolvers
     - DouyinResolver
     - YtDlpResolver
     - Future Platform Resolvers
  -> 外部工具
     - yt-dlp
     - ffmpeg
     - 未来 ASR / LLM / 翻译服务
  -> 临时目录 / 未来对象存储 / 未来数据库
```

## 当前原则

- 不再把 `yt-dlp` 视为唯一方案，而是作为通用兜底能力。
- 抖音等特殊平台走专用 Resolver。
- 公网版本默认不接收用户 Cookie。
- 下载功能先沉淀，第四阶段优先开发 AI/Pro 功能。
- 每个阶段先出方案，人工确认后开发，开发后自主测试，最后人工验收。
