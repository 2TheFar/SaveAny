# SaveAny 第四阶段竞品调研

调研时间：2026-05-06

## 调研范围

本次调研围绕 SaveAny 第四阶段“视频总结、字幕提取、字幕翻译、音频提取”等 Pro 能力，重点观察两个竞品：

- BibiGPT：https://bibigpt.co/
- NoteGPT BiliBili Summarizer：https://notegpt.io/cn/bilibili-summarizer

说明：本报告基于公开官网、公开文档与公开定价页整理，未登录付费账号进行深度试用。

## 项目背景对齐

SaveAny 当前已经完成“公开视频下载”MVP 闭环，架构是：

```text
Next.js 产品入口 + BFF
FastAPI 下载与任务后端
Resolver 平台解析层
yt-dlp / ffmpeg 外部处理工具
本地临时文件存储
```

第四阶段不应另起一套 AI 系统，而应继续复用统一任务模型：

```text
视频链接
-> 解析媒体信息
-> 创建 AI 任务
-> 获取字幕或提取音频
-> 转写 / 翻译 / 总结
-> 结构化结果返回
```

## 竞品一：BibiGPT

### 产品定位

BibiGPT 定位为 AI 音视频学习助手，核心卖点是让用户更快理解音视频内容，并把视频变成可复用知识。首页强调 1M+ 用户、5M+ 总结、30+ 平台等规模信号。

### 核心流程

公开文档展示的基础流程非常直接：

```text
复制视频或音频链接
-> 粘贴到输入框，或通过粘贴按钮自动填充
-> 自动/一键生成总结
-> 查看总结结果
-> 导出或继续使用结果
```

这个流程对 SaveAny 很有参考价值：用户心智不是“配置 AI 参数”，而是“粘贴链接后立刻拿结果”。

### 结果页能力

BibiGPT 的总结详情页围绕“多视角理解内容”设计：

- 总结摘要：整体摘要 + 章节摘要。
- 思维导图：支持 Markmap / XMind 两类展示。
- 字幕列表：带时间戳，可跳转到对应位置。
- 文章视图：原始脚本 + AI 改写。
- 视频问答：围绕视频内容继续追问。
- 侧边栏导航：章节跳转、时间戳跳转。

对 SaveAny 的启发：第一阶段不必一次做全，但结果结构应提前设计成可扩展，而不是只返回一段纯文本。

### 平台覆盖

BibiGPT 覆盖很广：

- 国内视频：Bilibili、抖音、快手、小红书、西瓜视频、今日头条、可灵、优酷。
- 海外视频：YouTube、TikTok、Instagram、Lemon8。
- 音频：喜马拉雅、小宇宙 FM、Apple Podcasts、Spotify。
- 教育：Coursera、DeepLearning.AI、TED。
- 其他：Twitter 视频、Substack。
- 本地文件：支持常见视频/音频格式，公开文档提到单文件 2GB 限制。

对 SaveAny 的启发：当前已有 YouTube、Bilibili、Douyin 基础能力，第四阶段应先用这些已有 Resolver 做闭环，不急着追求平台数量。

### API 与参数能力

BibiGPT 公开了 beta API，能力包括：

- URL 总结。
- 自定义总结配置。
- 章节总结。
- 提交异步任务与查询状态。
- 获取字幕。
- 字幕润色。
- 改写为文章。
- 围绕内容问答。

可配置项包括输出语言、是否展示时间戳、大纲层级、摘要长短、自定义 Prompt、是否刷新缓存、最大时长限制等。

对 SaveAny 的启发：后端接口要从一开始就保留结构化参数位置，例如 `language`、`summaryStyle`、`includeTranscript`、`maxDuration`、`forceRefresh`。

### 商业化

BibiGPT 采用订阅 + 按需购买：

- Plus：约 $19.80/月。
- Pro：约 $34.80/月。
- 会员合伙人：一次性 $888。
- 注册赠送免费体验时长。
- 支持 7 天退款。

它把高级模型、笔记软件同步、文章改写、视觉分析、图文生成等放到更高档位。

## 竞品二：NoteGPT BiliBili Summarizer

### 产品定位

NoteGPT 的 BiliBili Summarizer 是一个 SEO 定向工具页，本质是 NoteGPT 全站 AI 学习工具矩阵中的一个入口。它强调“B 站视频总结、转录、深度总结、思维导图、多语言翻译、AI 对话”。

### 核心流程

页面描述的流程是：

```text
输入 Bilibili 视频链接
-> 点击生成
-> 获取深度总结、思维导图、转录文本
-> 与 AI 继续对话
-> 保存到工作台
```

它特别强调低门槛和即时感，例如“简单三步”“快速获得总结”等表达。

### 结果能力

NoteGPT 页面重点包装了：

- 深度总结。
- 思维导图。
- 转录文本。
- 多语言翻译。
- AI 对话。
- 保存到工作台。
- 导出 PDF / Word。
- 移动端可用。

对 SaveAny 的启发：结果页需要给用户“可带走”的东西，最小可行版本可以先支持 Markdown 复制/下载，后续再做 PDF、Word、工作台历史。

### 商业化与额度

NoteGPT 的定价更偏 SaaS 工具矩阵：

- Pro：约 $9/月，提供基础额度与较小处理上限。
- Unlimited：约 $19.92/月，扩大额度、并发和文件上限。
- Max：约 $69/月，面向更高强度使用。

公开定价页把处理能力拆得很细，例如：

- 带字幕的 YouTube 处理上限更宽。
- 无字幕视频有分钟数限制。
- 本地音视频有文件大小限制。
- 不同套餐有不同并发数量。
- 额度分为 Basic Quotas 与 Premium Credits。

对 SaveAny 的启发：后续做付费时，额度不宜只按“次数”设计，最好同时考虑视频时长、是否需要 ASR、并发数、本地文件大小、模型等级。

### 增长策略

NoteGPT 的强项不是单个 Bilibili 工具，而是大量垂直工具页组成的 SEO 矩阵，例如 YouTube、PDF、PPT、音频、思维导图、学习工具、写作工具等。Bilibili Summarizer 页面只是其中一个获客入口。

对 SaveAny 的启发：SaveAny 早期不适合铺太多 SEO 页，应先把“下载 + AI 总结”这个差异化闭环做强。等核心能力稳定后，再拆分平台页和功能页。

## 对比总结

| 维度 | BibiGPT | NoteGPT | SaveAny 可借鉴点 |
| --- | --- | --- | --- |
| 核心定位 | 音视频内容学习助手 | 全站 AI 学习工具矩阵 | 先聚焦“视频保存 + 内容理解” |
| 入口方式 | 粘贴链接 / 本地文件 / API | 垂直工具页输入链接 | 继续强化粘贴链接心智 |
| 输出结果 | 摘要、章节、思维导图、字幕、文章、问答 | 摘要、转录、思维导图、翻译、工作台 | MVP 先做摘要、章节、要点、字幕来源 |
| 平台覆盖 | 非常广，含音频和教育平台 | 单页聚焦 Bilibili，全站覆盖面广 | 先复用 YouTube/Bilibili/Douyin |
| 技术产品化 | 有开放 API、缓存、Prompt 配置 | 强调工具矩阵与额度体系 | 先设计结构化接口，暂缓开放 API |
| 商业化 | 订阅 + 按需购买 + 会员合伙人 | 订阅套餐 + Basic/Premium 额度 | 后续额度应按时长、ASR、并发、模型拆分 |

## SaveAny 第四阶段机会点

SaveAny 不应简单复制“AI 总结工具”，而应利用已有下载能力形成差异化：

```text
别人：粘贴链接 -> 总结
SaveAny：粘贴链接 -> 解析/保存视频 -> 提取字幕/音频 -> 总结/翻译/导出 -> 保留原始素材与知识结果
```

更适合 SaveAny 的阶段目标：

1. 先跑通视频总结任务闭环。
2. 优先使用平台字幕，降低成本和处理时间。
3. 没有字幕时，再走音频提取 + ASR。
4. 结果先返回结构化 JSON，前端展示摘要、章节、要点、时间戳。
5. 暂时不做账号、支付、笔记同步、开放 API、复杂思维导图。

## 建议的 MVP 功能边界

### 第一批建议实现

- `POST /api/tasks/summarize`：创建视频总结任务。
- `GET /api/tasks/{task_id}`：复用现有任务查询。
- 字幕优先策略：优先平台字幕，其次音频提取。
- 结果结构：

```json
{
  "summary": "整体摘要",
  "chapters": [
    {
      "title": "章节标题",
      "startTime": 0,
      "endTime": 120,
      "summary": "章节摘要"
    }
  ],
  "keyPoints": ["核心要点 1", "核心要点 2"],
  "transcript": [
    {
      "startTime": 0,
      "endTime": 8,
      "text": "字幕文本"
    }
  ],
  "source": {
    "usedSubtitle": true,
    "usedAsr": false,
    "language": "zh"
  }
}
```

### 暂缓实现

- 思维导图编辑器。
- 视频问答多轮对话。
- Notion / Obsidian 同步。
- 开放 API。
- 复杂额度系统。
- PDF / Word 导出。
- 批量频道总结。
- 本地大文件上传。

## 关键产品原则

- 普通用户只看到“总结视频”，不要先暴露复杂 AI 参数。
- 后端必须保留结构化参数，方便后续扩展。
- AI 任务继续使用现有任务状态：`pending`、`running`、`success`、`failed`、`expired`。
- 继续复用已有错误模型，不重新发明 AI 错误类型。
- 公网版本继续默认不接收、不保存、不使用用户 Cookie。
- 第一阶段验收目标应是可演示，而不是功能最全。

## 下一步待人工确认

进入方案设计前，建议先确认以下问题：

1. 第一版视频总结是否只支持公开视频，不处理需要登录、会员、Cookie 的内容？
2. 第一版平台范围是否限定为 YouTube + Bilibili，Douyin 在字幕/ASR链路成熟后再接？
3. AI 技术栈优先选哪条路线：OpenAI-compatible 云端模型、国内模型 API、本地 Whisper + 云端 LLM，还是先做 mock 结果打通任务链路？
4. 前端入口是直接放在现有首页工作台，还是新增独立的“视频总结”Tab/页面？
