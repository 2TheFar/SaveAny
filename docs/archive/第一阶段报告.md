# SaveAny 第一阶段报告

生成时间：2026-05-06

## 1. 阶段定位

第一阶段是“可行性验证 MVP”，不是正式发行版。

本阶段验证的是最小核心链路：

```text
用户粘贴公开视频链接
  ↓
后端解析视频信息
  ↓
后端下载视频文件
  ↓
浏览器下载生成文件
```

阶段目标是证明 SaveAny 作为 Web 视频保存工具具备技术可行性，而不是一次性解决所有平台、所有清晰度、账号、支付、队列、部署和风控问题。

## 2. 已完成内容

### 2.1 产品界面

- 创建了 SaveAny Web MVP。
- 首页包含导航、核心标题、链接输入框、质量选择、状态提示、解析结果、支持平台和 Pro 能力展示。
- UI 参考 `ai.codefather.cn/painting`：白底、强蓝主色、大标题、圆角搜索框、卡片式内容、柔和阴影、移动端单列。
- Pro 目前只做展示，不接真实支付。

### 2.2 下载链路

- 支持单个公开视频链接。
- 支持解析标题、封面、时长和格式摘要。
- 支持质量选择：最佳、1080p、720p、仅音频。
- 后端通过 `yt-dlp` CLI 下载文件。
- 下载文件保存到 `.saveany-cache` 临时目录。
- 浏览器通过文件接口下载后端生成的文件。
- 增加了 6 小时临时文件清理逻辑。

### 2.3 API

| API | 作用 |
| --- | --- |
| `POST /api/video/info` | 解析视频元信息 |
| `POST /api/video/download` | 下载视频并生成临时文件 |
| `GET /api/video/file/:id` | 返回下载文件 |

### 2.4 验证结果

- `npm run lint` 通过。
- `npm run build` 通过。
- 首页可正常访问。
- 非法 URL 有友好错误提示。
- 公开视频解析成功。
- 公开视频 720p 下载成功。
- 文件接口可返回生成后的文件。
- 已用浏览器截图检查桌面端和移动端。
- 已修复移动端标题溢出问题。

## 3. 当前技术栈

| 模块 | 当前方案 |
| --- | --- |
| 前端框架 | Next.js 16 + React |
| 语言 | TypeScript |
| 样式 | 原生 CSS |
| 图标 | lucide-react |
| 后端 API | Next.js Route Handlers |
| 下载执行 | Node.js 调用外部 `yt-dlp` CLI |
| 音视频依赖 | 外部 `ffmpeg` |
| 数据库 | 暂无 |
| 登录/支付 | 暂无 |
| 包管理 | npm |

当前架构：

```text
浏览器
  ↓
Next.js 页面
  ↓
Next.js Route Handlers
  ↓
Node.js child_process
  ↓
yt-dlp + ffmpeg
  ↓
.saveany-cache
  ↓
浏览器下载文件
```

## 4. 当前结论

第一阶段证明了：

- SaveAny 的产品形态可行。
- Web 页面 + 后端下载的链路可行。
- `yt-dlp` 可作为通用下载器完成一部分公开视频下载。
- Next.js 单体适合作为 MVP 起步方式。

但第一阶段也暴露了正式化前必须面对的问题：

- 图片缩略图不应由前端直连第三方地址。
- 固定展示 1080p/720p 不够准确，应展示真实可用清晰度。
- 防盗链、403、503 需要后端代理和结构化错误处理。
- 只依赖 `yt-dlp` 会限制对抖音等特殊平台的支持。
- 当前同步下载模式不适合长任务和批量任务。
- 当前没有数据库、队列、账号、支付、限流和部署自检。

## 5. 关于 Next.js 的判断

没有及时提出“平台专用解析器”方案，不是 Next.js 技术栈导致的。

Next.js 可以继续承担：

- 产品页面。
- 官网/SEO。
- 工作台 UI。
- 轻量 BFF。
- 将 API 请求转发到 FastAPI 或其他后端服务。

这次判断不足的真正原因是：第一阶段把后端下载能力建模成了“所有平台都走 `yt-dlp`”的单一路径，而没有更早抽象出“平台识别 + 平台专用 Resolver + 通用兜底”的解析架构。

因此，问题不在 Next.js，而在后端解析层抽象不够。

## 6. 阶段结论

第一阶段可以归档为：

```text
MVP 可行性验证完成。
当前方案可以继续承接第二阶段，但不能直接视为正式发行架构。
```

下一阶段应聚焦：

- 重整解析架构。
- 引入平台专用 Resolver 概念。
- 解决缩略图代理、防盗链、真实清晰度和任务状态。
- 为未来 FastAPI 下载服务预留边界。
